# go-fast-email against the tools in use today

Generated by `bench/report_doc.py`; do not edit. Numbers are from one machine and compare tools on that machine only.

Machine: AMD Ryzen 9 9900X 12-Core Processor, 24 logical cores, Linux-6.18.60-1-lts-x86_64-with-glibc2.44, Python 3.13.18, go version go1.27.3-X:nodwarf5 linux/amd64. Each run waited for the machine to be quiet and was repeated if other processes used it meanwhile (`measure.py`).

Versions: mail-parser 4.11.0, eml-parser 4.7.1, kreuzberg 4.10.4, striprtf 0.0.35, odfpy 1.4.1, pandas 3.1.1, pandoc 3.11, calamine (crate) 0.31.0, mail-parser (crate) 0.11.9, rtf-parser (crate) 0.4.3.

Each tool reads every file in one long-lived process, the way a pipeline does, with one worker and with 24; the time of a file is the call alone, after its bytes are read. Wall time, CPU time and peak memory are of the whole process tree.

## Email

### go-fast-email and `GOGC`

Go's garbage collector can be given more memory for less work with `GOGC` in the environment (or `debug.SetGCPercent`); the library and its command keep Go's default, 100. The same run as above with each setting (wall time, peak memory):
